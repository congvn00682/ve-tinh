# Provided experimental results

The [cuda_aid_9class/](cuda_aid_9class/) bundle was added to the repository on
04/10/2026 from 12 user-provided CSVs. Original files were copied byte for byte;
source filenames and SHA-256 hashes are in
[provenance.json](cuda_aid_9class/provenance.json). This directory stores research
results independently of `.orca/drops` when the repository is cloned.

## Protocol and evidence status

- RGB scene classification, nine shared classes, source → AID. No same-domain
  testing or domain-gap reporting.
- Source: 900 images, 100 images per class; NWPU-RESISC45 origin confirmed by the
  user, [Hugging Face version](https://huggingface.co/datasets/blanchon/RESISC45).
- Target: AID, 180 images per condition/seed, 20 images per class; origin confirmed
  by the user, [Hugging Face version](https://huggingface.co/datasets/blanchon/AID).
- CUDA is the user-reported environment. Whether CUDA was used for training,
  testing, or both is unknown; GPU model, CUDA/PyTorch versions, and a run
  environment lockfile are not available.
- Seeds in the CSVs: 13, 37, 73. Validation folds of the provided runs lack
  metadata for comparison. Current code defaults assign folds 0, 1, 2; do not
  assume historical runs necessarily used those defaults.
- The training profile has not been confirmed as baseline or weather_robust.
  These results do not yet demonstrate a benefit from weather_robust.
- The AID set has already been viewed to analyze improvements: treat current
  results as exploratory. An unseen target set and a fixed protocol are required
  before final evaluation.

[DATA.md](../DATA.md) provides a frozen manifest, matched revision, and ZIP for
the current 900 source images. This manifest has not been verified as the source
manifest of the supplied Windows runs; do not use a new snapshot to fill in
historical provenance.
The three test directories were subsequently provided and saved in `data/aid_subsets/`.
[data_verification.json](cuda_aid_9class/data_verification.json) records that the
reconstructed clean manifest matches the hash of all 12 runs, and that bright/lowres
filenames and labels match every CSV. Initial import provenance is preserved to
show which files were available when the CSVs were received.

## Bright and lowres

Original prediction sources: [bright](cuda_aid_9class/raw/bright/) and
[lowres](cuda_aid_9class/raw/lowres/), one CSV per model/condition.
Each file has 540 rows = 180 images × three seeds. Filenames/labels match across
models and seeds within each condition. The provided images match filenames/labels
in every CSV; current image bytes are frozen with SHA-256 in the three target
manifests. Prediction CSVs do not record image hashes, so current image bytes
cannot yet be verified against hashes recorded during historical bright/lowres runs.

- Bright: the user describes brightness increased by 30 and contrast by 100;
  tool, parameter scale, formula, processing order, and clipping are unknown.
- Lowres: the user describes blurring; all 180 provided images have 300×300 headers,
  while clean/bright are 600×600. Resize kernel and blur sigma are unknown.
- The images have not been confirmed as generated by `optical-proxies-v1` in the current code.
- These checkpoints cannot be confirmed as identical to those used for clean
  testing: prediction CSVs only contain Seed, File_Name, True_Label,
  Predicted_Label, Confidence, and Is_Correct; no checkpoint hash or target
  manifest hash is included.

Recalculated directly from true and predicted labels, mean ± sample SD (%):

| Model | Bright accuracy | Bright macro-F1 | Lowres accuracy | Lowres macro-F1 |
|---|---:|---:|---:|---:|
| SmallCNN | 45.19 ± 5.89 | 39.20 ± 6.60 | 59.26 ± 0.64 | 56.91 ± 0.86 |
| ResNet18 scratch | 54.63 ± 5.04 | 50.02 ± 5.62 | 67.59 ± 1.16 | 67.02 ± 1.27 |
| ResNet18 pretrained | 80.56 ± 1.92 | 79.16 ± 2.72 | 86.85 ± 0.32 | 86.52 ± 0.37 |
| DeiT-Tiny pretrained | 87.22 ± 1.11 | 86.67 ± 1.88 | 85.93 ± 2.25 | 85.91 ± 2.45 |

DeiT has the highest mean on bright. Pretrained ResNet is ahead by 0.93 accuracy
points on lowres; their ranking changes by seed, and no statistical test or CI
is available. These are observations on provided data, not general conclusions.

Per-class weaknesses: airport recall on bright is 48.33% for DeiT and 31.67%
for pretrained ResNet. On lowres, dense_residential recall is 41.67% and 40.00%
respectively; a common confusion is dense_residential → commercial_area.
SmallCNN correctly identifies no dense_residential images in any of the three lowres runs.

## Limitations of comparisons between conditions

Bright and lowres have no overlapping filename/label pairs; for example,
airport_41.jpg–airport_60.jpg versus airport_61.jpg–airport_80.jpg.
Whether these are different images or renamed versions of the same originals
is unknown; no original-image mapping is available for pairing. Clean now has
a manifest matching the historical hash, but clean predictions and checkpoint
files remain unavailable. Therefore, tables present metrics for each set without
exporting a clean-to-degraded drop.

Three seeds reuse the same image list within each condition. 540 prediction
rows are not 540 independent images; 4,320 rows across eight files are not
4,320 independent samples. Mean ± SD measures variation between runs, not a
confidence interval. These CSVs do not establish real storm, real weather,
flooding, or damage recognition capabilities.

## Files for checking and reproducing tables

| Artifact | Contents |
|---|---|
| `raw/clean/*.csv` | Four user-provided clean tables, preserved byte for byte |
| `raw/{bright,lowres}/*.csv` | Eight user-provided prediction tables, preserved byte for byte |
| `provenance.json` | File sources, SHA-256, user-reported information, and unverified items |
| [condition_runs.csv](cuda_aid_9class/condition_runs.csv) | 24 transformed-condition runs: correct/incorrect counts, accuracy, balanced accuracy, macro P/R/F1 |
| [condition_models.csv](cuda_aid_9class/condition_models.csv) | Mean/sample SD of eight model/condition pairs |
| [per_class_condition_runs.csv](cuda_aid_9class/per_class_condition_runs.csv) | 216 model/seed/condition/class rows, support=20 |
| [per_class_condition_models.csv](cuda_aid_9class/per_class_condition_models.csv) | Precision/recall/F1 mean/SD for 72 model/condition/class groups |
| [confusion_matrices/](cuda_aid_9class/confusion_matrices/) | 24 count matrices from predictions; rows are true labels, columns are predicted labels |
| [verification.json](cuda_aid_9class/verification.json) | CSV consistency check results and verification limitations |
| [data_verification.json](cuda_aid_9class/data_verification.json) | Additional image audit after CSV import: clean manifest hash and bright/lowres filenames/labels |

CSV metrics use the 0–1 scale; Markdown tables convert them to percentages for
readability. To check input hashes and regenerate tables from the repository
root, use Python >=3.10; PyTorch, NumPy, and Matplotlib are not required:

```bash
python scripts/summarize_submitted_results.py
```

The command preserves `raw/` and `provenance.json` and replaces derived tables
with the same names; it refuses to proceed if raw CSVs differ from their import
hashes or the tables are inconsistent. This reproduces calculations from CSVs;
it does not rerun image training/evaluation.
Provided images and target manifests are in `data/aid_subsets/` and
`data/provenance/`; ZIPs and the restore script are documented in [DATA.md](../DATA.md).
Checkpoints, training histories, and bright/lowres generation code have not yet
been provided. Those artifacts cannot be recovered from summary tables.
`verification.json` covers CSV checks only; new image evidence is recorded
separately in `data_verification.json`.
